## 3. 修复计划（对抗性优先）

### 3.1 outbox lane 阻塞（F1）——高优先

**问题**：pumpLane 失败 → `lane.unshift(env.id)`（回队头）+ `await sleep(backoff)` → **单条持续失败阻塞整个 lane**（严格 FIFO vs 可用性冲突）。

**修复**：

1. **失败消息不阻塞 lane**：失败 → 移出队头，**排到队尾**（`lane.push`）→ 后续消息先发（牺牲严格 FIFO，换取会话可用性——飞书会话可接受）
2. **退避有界**：确认 `backoffMaxMs` 默认值合理（如 ≤60s），attempts 封顶（如 50 次后转 fatal 或降级）
3. **重试观察**：失败消息在队尾重试，不堵新消息

### 3.2 status 启动即时刷新（F5）——中优先

**修复**：startBridge 成功后立即 `statusStore.update({ outboxPending, outboxFailed })`（不等 60s 定时器）。

### 3.3 message_end 转发验证（P0 功能）

**验证**：每轮 assistant 输出转发是否真实工作——需实机验证（用户发多轮任务消息）。
**边界**：空输出跳过 ✓（已实现）；工具调用轮无文本 ✓。
