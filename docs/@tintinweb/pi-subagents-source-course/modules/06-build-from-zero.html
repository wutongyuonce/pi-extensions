把读懂转化为能重建

从零做一个最小子代理扩展：按边界生长，不按文件堆叠

先做可观察的最小闭环，再加策略、隔离与 UI。每一步都应有相应测试：项目的 test/ 正是把这些边界固定下来的可执行规格。

1
定义运行记录

设计 AgentRecord：id、prompt、status、结果、AbortController。先只支持一个前台任务。

2
封装 runAgent

创建 AgentSession、发送 prompt、收集最终文本；不让 UI 直接接触会话。

3
引入 Manager

把记录表、停止、恢复与完成回调集中；再加后台队列和并发计数。

4
配置化角色

将模型、工具、系统提示词从代码移到 AgentConfig 与 Markdown frontmatter。

5
补齐边界

处理工作树、内存、转录、调度、扩展动态工具与错误状态。

6
最后做 UI

Widget/Fleet/Viewer 从 Manager 读取事实，绝不自己维护第二份任务状态。

export function getLifetimeTotal(u?: LifetimeUsage): number {
  if (!u) return 0;
  return u.input + u.output + u.cacheWrite;
}
逐行定位
可选参数：调用方未拿到统计时也能安全展示 0。
单一口径：token 总量只在这里定义；UI 不应各自相加，以免统计口径漂移。
刻意排除 cacheRead：注释说明这是产品语义选择，不是遗漏。
