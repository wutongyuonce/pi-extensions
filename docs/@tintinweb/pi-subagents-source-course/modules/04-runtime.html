真正运行前发生了什么

runAgent() 把抽象配置装配成一个独立 AgentSession

它是本项目最重要的装配函数：选择有效 cwd，加载 extension 与 skill，解析模型和思考级别，限制工具，然后订阅流式事件并发送 prompt。

1
装配输入

合并类型配置、调用选项、父上下文与环境信息。

2
建立资源加载器

按 extensions / skills / prompt_mode 过滤资源；隔离模式可全部关闭。

3
建会话并绑定扩展

先构造工具边界，再允许延迟注册的扩展工具进入可见范围。

4
订阅事件后 prompt

收集文本、工具活动、token、压缩与 turn 上限，结束时必定解绑。

真实源码 · src/agent-runner.ts
const { session } = await createAgentSession(sessionOpts);

session.setSessionName(
  options.agentId ? `${baseSessionName}#${options.agentId.slice(0, 8)}` : baseSessionName,
);

await session.bindExtensions({
  onError: (err) => {
    options.onToolActivity?.({ type: "end", toolName: `extension-error:${err.extensionPath}` });
  },
});
逐行定位
createAgentSession：把前面拼好的 options 交给 pi，得到独立运行容器。
setSessionName：用类型和短 id 命名，便于日志、会话列表和问题追踪。
bindExtensions：触发扩展的初始化；错误转换成工具活动，让 UI 与调用者看得见。

工具作用域

tools 决定允许哪些工具；extensions 决定哪些扩展会加载。两者刻意分离。
