状态机与并发背压

AgentManager 是项目的交通指挥塔

每个任务先成为 AgentRecord；后台任务达到并发上限时进 FIFO 队列，前台任务绕过队列，因为父任务本来就在等待它。

真实源码 · src/agent-manager.ts
if (options.isBackground && !options.bypassQueue && this.runningBackground >= this.maxConcurrent) {
  this.queue.push({ id, args });
  return id;
}

this.startAgent(id, record, args);
return id;
逐行定位
三个条件：只有普通后台任务才受限；定时任务可用 bypassQueue 保证触发时效。
queue.push：保存全部启动参数，而不是只保存 id；以后才能原样启动。
return id：调用者立刻获得可查询、停止、转向的稳定句柄。
startAgent：非排队路径立即启动，保持 spawn 的统一出口。
🧭
定位 bug 的第一问

看到“任务不动了”，先看 record 的 status 和 runningBackground；再看 queue 是否被 drain。不要先怀疑模型。

const { session } = await createAgentSession(sessionOpts);

session.setSessionName(
  options.agentId ? `${baseSessionName}#${options.agentId.slice(0, 8)}` : baseSessionName,

await session.bindExtensions({

逐行定位

把失败变成可解释状态

可靠性不是一个 try/catch，而是一组明确边界

这个项目将风险分散在专门模块：工作树隔离、内存路径安全、调度持久化锁、输出转录、模型范围与生命周期错误归类。每个模块只保护一种资源或约束。

🌳
worktree.ts

用临时 git worktree 隔离变更；完成后清理，若有更改则保留分支。

🗂️
memory.ts

拒绝危险名称与符号链接，避免代理记忆文件逃逸到非预期路径。

🔐
schedule-store.ts

JSON 存储配 PID 锁，避免同一会话的多个进程互相覆盖任务。

📜
output-file.ts

把流式对话写为 JSONL 转录，且可由配置关闭。

真实源码 · src/memory.ts
export function isUnsafeName(name: string): boolean {
  return name.includes("/") || name.includes("\\") || name === "." || name === "..";
}

export function isSymlink(filePath: string): boolean {
  try {
    return lstatSync(filePath).isSymbolicLink();
  } catch {
    return false;
  }
}
逐行定位
isUnsafeName：把路径分隔符和 . / .. 当作不安全输入，阻止目录穿越。
lstatSync：检查“链接本身”，不会跟随链接；这正是识别符号链接所需的语义。
catch → false：不存在的文件不是链接；调用者可继续按普通缺失文件处理。
⚠️
不要把“失败”压成一个状态

aborted、stopped、error、steered 的含义不同。保留差异，UI、通知与重试策略才不会说谎。

先做可观察的最小闭环，再加策略、隔离与 UI。每一步都应有相应测试：项目的 test/ 正是把这些边界固定下来的可执行规格。

3

4

5

6
最后做 UI

Widget/Fleet/Viewer 从 Manager 读取事实，绝不自己维护第二份任务状态。

真实源码 · src/usage.ts
export function getLifetimeTotal(u?: LifetimeUsage): number {
  if (!u) return 0;
  return u.input + u.output + u.cacheWrite;
}
逐行定位
可选参数：调用方未拿到统计时也能安全展示 0。
单一口径：token 总量只在这里定义；UI 不应各自相加，以免统计口径漂移。
刻意排除 cacheRead：注释说明这是产品语义选择，不是遗漏。
